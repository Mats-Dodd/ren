# REN-01 site

The manual's website. Not part of the dune build (see the root `dune`).

Astro + StyleX design system for the Ren programmer's manual.

    npm install
    npm run dev       # regenerates tokens, starts Astro
    npm run build     # tokens -> astro build -> relative asset URLs

## Layers (each imports only from the ones above it)

    src/system/palette.ts           canonical tokens (edit here)
    src/system/tokens.stylex.ts     GENERATED by scripts/gen-tokens.ts
    src/system/primitives/          H, P, Label, Code, A, Rule, Aside, Frame, Inline
    src/system/components/          SpecBlock, Pinout, LampPanel, Listing,
                                    FaultTable, Callout, MemoryMap, TimingDiagram
    src/system/chrome/              RunningHeader, RunningFooter
    src/pages/                      index, book/*.mdx, standards (living appendix)

## Rules

- All `stylex.create` calls live in `.ts` files. StyleX does not compile
  `.astro` frontmatter; templates only spread `stylex.attrs(...)`.
- StyleX can't evaluate values imported from plain modules, so palette.ts is
  the source of truth and the token file is generated from it.
- StyleX runs unlayered (`useCSSLayers: false`) so host/blog CSS can't override
  tokens. The reset sits in `@layer reset` so it always loses.
- Figure data follows `src/lib/schema.ts` (Signature, MemoryRow, Trace).
  `ren doc` should eventually emit these shapes from real code.
- Listings load real files from `src/content/listings/`.

## Listings and compiler output

`src/content/listings/` holds the book's programs and what the compiler prints
for them. The `.txt` outputs were transcribed from the error format in
`test/test_errors.ml` and `examples/examples.t`; they should become cram tests
so a change to the compiler's wording shows up as a diff here.
